# Автотесты BookClub

Тесты не заглядывают в код сайта. Они запускают сайт отдельно и общаются с ним так же, как посетитель:
по сети и через настоящий браузер. Поэтому тесты не ломаются от переименований внутри кода,
а находят то, что заметил бы пользователь.

## Что проверяется

| Папка | Как проверяется | Что внутри |
|---|---|---|
| `Api/` | запросы к API (около 180 проверок) | вход и токены, каталог, клубы, создание отбора, голосование, запечатанный конверт, закрытие и подсчёт, рецензии и анонимность, личная полка, админка, правила самой базы данных |
| `E2E/` | настоящий браузер Chromium (Playwright) | регистрация и вход, клуб, весь путь отбора от создания до вскрытого конверта, каталог, полка, рецензия, админка, показ чужого текста без выполнения кода |

Особенно подробно проверены места, где ошибка дороже всего:

- **Один человек, один голос**, в том числе когда пять запросов приходят одновременно.
- **Запечатанный конверт**: пока отбор идёт, сервер не отдаёт распределение голосов никому, даже админу клуба.
- **Тайна голоса**: в таблице голосов нет столбца с пользователем, а в ответах нет имён проголосовавших.
- **Токены**: чужая подпись, просроченный, подменённая роль, «без подписи» отвергаются; блокировка действует сразу.
- **Анонимные рецензии** не раскрывают автора никому, кроме админа (для модерации).
- **Правила базы**: уникальность, допустимые роли и статусы, диапазоны оценок держит сама PostgreSQL.

## Как это запускается

Каждый коммит проверяет GitHub Actions (файл `.github/workflows/tests.yml`):

1. поднимает одноразовую PostgreSQL,
2. создаёт таблицы теми же миграциями, что и у вас,
3. запускает сайт,
4. прогоняет API-тесты, затем браузерные,
5. кладёт на страницу запуска отчёт: упавшие тесты с причиной и список прошедших.

Если браузерный тест упал, к запуску прикладывается снимок экрана на момент падения (раздел Artifacts).

## Запуск на своём компьютере

Нужны .NET 10 SDK и отдельная **тестовая** база PostgreSQL (тесты создают в ней много записей; не используйте
рабочую базу).

```powershell
# 1. Создайте пустую тестовую базу и примените миграции к ней
dotnet ef database update --connection "Host=127.0.0.1;Database=bookclub_test;Username=postgres;Password=postgres"

# 2. Запустите сайт, подключив его к тестовой базе
$env:ConnectionStrings__DefaultConnection = "Host=127.0.0.1;Database=bookclub_test;Username=postgres;Password=postgres"
$env:Jwt__Key = "любой-длинный-тестовый-ключ-не-короче-32-знаков"
dotnet run --urls http://127.0.0.1:5153

# 3. В другом окне запустите тесты (те же значения ключа и базы)
$env:BOOKCLUB_URL = "http://127.0.0.1:5153"
$env:BOOKCLUB_TEST_DB = "Host=127.0.0.1;Database=bookclub_test;Username=postgres;Password=postgres"
$env:BOOKCLUB_TEST_JWT_KEY = "любой-длинный-тестовый-ключ-не-короче-32-знаков"
dotnet test tests/BookClub.Tests --filter "Category=Api"

# Браузерные тесты: один раз скачайте браузер, потом запускайте
dotnet build tests/BookClub.Tests
pwsh tests/BookClub.Tests/bin/Debug/net10.0/playwright.ps1 install chromium
dotnet test tests/BookClub.Tests --filter "Category=E2E"
```

Если не задать `BOOKCLUB_TEST_JWT_KEY`, семь проверок токенов будут пропущены (они собирают токены вручную и
должны знать секрет сайта).

## Как устроены тесты

- Каждый тест создаёт своих пользователей, книги и клубы со случайными именами, поэтому тесты не зависят друг от друга
  и от порядка запуска.
- Первого админа сайта через API завести нельзя, поэтому тесты выдают роль напрямую в базе (`TestUser.CreateAdmin`).
  То же приходится делать вам при первом запуске сайта.
- Чтобы «состарить» отбор без ожидания, тесты сдвигают срок закрытия прямо в базе.
- Названия тестов написаны по-русски: именно их вы увидите в отчёте.
