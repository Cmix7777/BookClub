Сайт для книжных клубов. У каждого человека есть своя полка книг (хочу прочитать, читаю, прочитал), книги можно оценивать и рецензировать, а в закрытых клубах следующую книгу выбирают голосованием, где никто не видит, кто за что проголосовал.

Это учебный проект на ASP.NET Core. Сам сайт небольшой, поэтому я использовал его ещё и как полигон для тестирования: к нему написаны автоматические проверки на нескольких уровнях, и все они запускаются на чистой машине GitHub при каждом изменении. Про это ниже.

## Что умеет сайт

Регистрация и вход выдают токен JWT, пароли хранятся в виде хэша BCrypt. В каталоге можно смотреть книги и добавлять свои, а на личной полке отмечать статус и оценку. К книге можно написать рецензию с оценкой от 1 до 5, по желанию анонимную: имя автора тогда видит только админ сайта, для модерации.

Клуб создаёт любой человек, остальные в него вступают. Внутри клуба открывается отбор: несколько книг на выбор и срок голосования. Один человек голосует один раз, пока отбор идёт, распределение голосов не видит никто («запечатанный конверт»), а после закрытия, вручную или по таймеру, результат вскрывается. Кто за что голосовал, не хранится вообще: в таблице голосов нет столбца с пользователем, а факт участия записан отдельно.

У админа сайта есть панель: общая статистика, блокировка пользователей и смена ролей, модерация рецензий и поиск дубликатов в каталоге.

## Технологии

ASP.NET Core Web API на .NET 10, Entity Framework Core с PostgreSQL (Npgsql), авторизация по JWT, Swagger в режиме разработки. Страница сайта лежит в `wwwroot/index.html` и работает с тем же API.

## Как проверяется качество

Все проверки лежат в папке [`tests`](tests) и запускаются в GitHub Actions, а их итоги можно открыть во вкладке Actions.

- **Автотесты** (Tests): 221 проверка, из них 199 запросами к API и 22 сценария в настоящем браузере (Playwright). Сайт запускается отдельным процессом на одноразовой базе PostgreSQL, тесты ходят к нему по HTTP и ничего не знают о коде внутри.
- **Нагрузка** (Load): сценарии на k6 с порогами приёмки (время ответа, доля ошибок), плюс ступенчатый замер, где у сайта предел.
- **Проверка самих тестов** (Mutation): Stryker.NET портит код сайта по мелочи и смотрит, заметят ли это тесты. Сейчас они замечают 312 из 329 порч (94,8%), оставшиеся разобраны в [описании тестов](tests/README.md).

Как это устроено и как запустить на своём компьютере, написано в [tests/README.md](tests/README.md).

## Как запустить сайт

Нужны .NET 10 SDK, PostgreSQL и инструмент миграций (`dotnet tool install --global dotnet-ef`).

```powershell
# строка подключения и секретный ключ токенов хранятся в user-secrets, а не в репозитории
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Host=localhost;Database=bookclub;Username=postgres;Password=<ваш пароль>"
dotnet user-secrets set "Jwt:Key" "<любая длинная случайная строка, не короче 32 знаков>"

# создать таблицы и запустить
dotnet ef database update
dotnet run
```

Сайт откроется на `http://localhost:5153`, документация API (Swagger) на `/swagger`. Первого админа через API завести нельзя: нужно один раз выставить в базе у своего пользователя роль `Admin` (столбец `Role` таблицы `Users`).

## Устройство репозитория

В `Controllers` лежат конечные точки API по темам (авторизация, книги, полка, клубы, отборы, голоса, рецензии, пользователи, админка), в `Models` и `Data` модель данных и контекст базы, в `Migrations` миграции, в `Services` выпуск токенов. Папка `tests` содержит всё, что связано с проверками: `BookClub.Tests` (API и браузер), `BookClub.Mutation` (двойник для Stryker), `load` (сценарии k6).
